# F51–60: 管理・認証・セキュリティ 段階実装

このブランチの実装状況。CIとJava 1.7.10実クライアントによる動作確認に合格するまでは公開用途に使わないこと。

## 認証の境界

F51 はオフラインモードを変更せず、**明示的な別モード**として実装した。

- `server.properties` の `online-mode=true` または `--online-mode` でオンライン認証を有効化する。設定ファイルなし・引数なしでは従来どおりオフラインで起動する。設定ファイルを使う場合は `online-mode=true/false` の明示を必須とし、暗黙のモード切替を拒否する。
- Minecraft Java 1.7.10 / Protocol 5 の Encryption Request/Response、RSA-1024 PKCS#1 v1.5（当該プロトコル互換用）、16-byte shared secret、継続する双方向 AES-128-CFB8、署名付き2の補数 SHA-1 serverId、およびTLSでの Mojang `hasJoined` 検証を実装する。失敗・タイムアウト・不一致は拒否し、**オフラインUUIDへフォールバックしない**。
- オンラインセッションは確認済みUUIDを所有し、`players/verified/<UUID>.dat` とその関連保存ファイルに分離する。既存の `players/<offline-name>.dat` をオンラインログインで引き継がない。
- `ops.json` のOP権限は、オンラインで認証済みのUUIDだけを照合する。名前変更でも同じアカウントの権限は保持し、古い名前を再利用した別アカウントには引き継がない。UUIDは大文字・小文字を区別せず、重複したUUID登録は安全側に拒否する。オフラインUUID・未認証名では昇格しない。`/op Player` は対象の認証済みオンライン接続が必要で、再付与時は旧名の別登録を整理する。`/deop Player` は接続中の認証済みUUID（名前変更前の登録を含む）を解除し、未接続の対象は保存済み登録名で解除する。
- 安全上、**ホワイトリストは引き続き必須**。オンラインモードでも `white-list=false` は未対応として拒否する。`--insecure-offline-lan` は依然として偽装可能な危険なモード。
- CIのネイティブRust試験は、無改造Minecraft Java 1.7.10でのオンラインログインE2Eの代替ではない。正式公開まで実機接続・Mojangサービス障害・暗号化パケット境界・保存領域切替・管理権限・長時間負荷試験を行う。

## コンソール

- /list, /save, /time query daytime, /time set 6000, /weather query, /weather set clear, /tp Player 1 65 1
- /op Player, /deop Player, /ban Player reason, /pardon Player, /ban-ip 192.0.2.1 reason, /pardon-ip 192.0.2.1
- /kick Player reason, /whitelist reload, /whitelist list, /permission Player chat|build|interact allow|deny

起動時に管理JSONがなければ空配列で新規作成する。各JSONが不正・重複・非通常ファイルの場合は拒否する。ログイン時/セッション中はBANやホワイトリストが壊れると安全側で切断する。Mojang認証後に再検査し、認証検証中にBAN/ホワイトリストが変更されても保存領域を開かない。

## オンライン起動例とデータ移行注意

```properties
online-mode=true
white-list=true
server-ip=127.0.0.1
server-port=25565
```

既存オフラインデータを自動でオンラインUUIDへ移行しない。正当なアカウント所有者を確認してから管理者が個別のデータ移行手順を作成すること。オンライン時でも確認済みのユーザー名だけでファイルパスを決定しない。

## 手動試験項目

1. 無改造Java 1.7.10でログイン。一般プレイヤーの/saveは禁止、/listは可能。
2. /ban・/pardon・/ban-ip・/pardon-ipの反映と再起動後保持。
3. /kickの理由表示・セッション切断・最終保存。
4. IPv6とIPv4-mapped IPv6のBAN、1 IP接続枠超過・再接続回数制限。
5. チャット大量送信・異常文字列、permission反映、破損JSONのFail Closed。
6. admin-audit.jsonlのattempt/success/failureと監査I/O障害時の操作拒否。

注: RSA/AES実装とRust CIの成功は公開サーバーとしての十分な安全性を証明しない。無改造Minecraft Java 1.7.10実機試験、負荷試験、運用ハードニングが残るため、51〜60の最終受入は保留する。
