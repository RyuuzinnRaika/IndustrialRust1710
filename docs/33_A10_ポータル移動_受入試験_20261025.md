# A10 ポータル移動の Minecraft Java 1.7.10 受入試験

この文書は `codex/a10-portal-travel-20261025` の**受入手順**であり、実機で合格した記録ではありません。

## 事前条件

- Protocol 5 の無改造 Minecraft Java 1.7.10 を利用する。
- テスト専用の新規 IRW4 3ディメンションワールドを使い、本番ワールドを上書きしない。
- サーバ起動前に `DIM-1` と `DIM1` の保存先、バックアップ、`session.lock` を確認する。
- クライアントを再接続してもプレイヤーのDimension NBT・Inventory・XPが維持されることを確認する。

## 必須確認ケース

| No. | 操作 | 合格条件 |
| --- | --- | --- |
| 1 | Overworldで完全なネザーポータルを構築し80tick以上滞在 | Netherへ移動し、0x07 Respawn/Chunk/Positionを受信 |
| 2 | NetherからOverworldへ復帰 | X/Zの1:8座標比、足元の固体、2ブロックの空間を確認 |
| 3 | 額縁破損・不完全フレーム・流体中で移動を試行 | ディメンションを変更せず、アイテム等に変更がない |
| 4 | Endポータルの12フレームを完成させ中心に入る | Endに遷移し、正常にチャンクを描画 |
| 5 | プレイヤー死亡→復活 | Overworldに戻り、死亡時のXP/Inventory処理と同期 |
| 6 | 各ディメンションでログアウト・再ログイン | 保存されたDimension、座標、Inventory、XPを正確に復元 |
| 7 | 2クライアントで異なるディメンションに同時接続 | Entityやチャンクが異なるディメンション間へ漏洩しない |
| 8 | 移動前後に強制終了/ディスク書き込み失敗を再現 | 失効したCheckpointで二重転送されず、復旧後の状態が整合 |

## 既知の残課題

- 現在のA10変更は移動の基盤であり、Mob/コンテナ/その他サービスのディメンションごとの完全な分離は未検証です。
- A09のエンダードラゴン討伐後の出口ポータル生成・帰還は別実装と受入が必要です。
- このPRを本番環境へマージする条件: CI成功、ケース1〜6を少なくとも実機で合格、ケース7〜8の障害対策を文書化。未確認項目は合格と記載しない。
