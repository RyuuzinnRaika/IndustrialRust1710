# Minecraft 1.7.10 Rustバニラ最小サーバー（開発版）

## 目的

Mod JAR/Forge/FML/Configは扱わず、バニラ1.7.10（Protocol 5）用のRustネイティブサーバーを単独で動かす。

## 起動

~~~bash
cp config/whitelist.example.json whitelist.json
# whitelist.json に許可するプレイヤー名を指定してから起動
cargo run --release -p vanilla-server -- --bind 127.0.0.1:25565 --world ./world/flat.irw --whitelist ./whitelist.json
~~~

初期待受は127.0.0.1のみ。**ホワイトリストファイルがなければ起動拒否し、空リストは全員拒否**。LAN実験に限り --bind 0.0.0.0:25565 --insecure-offline-lan を**明示的に**指定できるが、**Microsoft/Mojangのユーザー認証なしのoffline-modeであり、許可済みプレイヤー名の偽装が可能**。インターネット公開してはいけない。最大8人まで。Minecraftの実ワールド保存先を指定しないこと。

## 今回の対応範囲

- Handshake、Status/Ping、Login Start、名前検査、offline UUID、Login Success。
- Play: Join Game、Creative、Spawn、Health、Player Abilities、Time、Position/Look。
- 5×5チャンク（80×80）の固定平坦地形と1.7.10のzlib圧縮Chunk Data。
- 20Hzの単調Tick時計と定期時刻通知（本格的なゲーム処理Tickではない）。
- ホワイトリストによる名前照合（JSONは毎ログインで読み直し、接続中も約2秒ごとに再照合）。
- 最大8人の同時ログイン（同名接続禁止）、1.7.10 Player Info/Named Entity Spawn/Teleport/Destroy、双方向プレイヤー表示・移動同期。
- 移動パケット、KeepAlive、共有チャット、/help、/save、/list。
- Creativeでの限定的な通常ブロックの設置・破壊、全接続プレイヤーへの更新送信、距離・座標検証。
- 変更ブロックの独自IRW1セーブ形式（サイズ制限、簡易破損検出、保存失敗時ロールバック）。
- プレイヤー座標をplayers/<小文字名>.datのgzip NBT形式に保存し、再接続時の位置を復元。旧バージョンのplayers/<小文字名>.jsonは新しいNBTが存在しない場合のみ読み取り、次回保存時にNBTへ移行。約5秒ごとと正常・異常切断時に記録。ファイル破損時はログイン前に拒否して管理者に修復を促す。
- 読込済みワールド（5×5チャンク）外への移動パケットは、サーバー権威側の位置へ戻す。

## 未対応

- Mod/Forge/FML、20TPS上の正式なブロック/エンティティ更新、Mob/AI、サバイバル、インベントリ/クラフト、物理・光源更新、レッドストーン。マルチの実機動作・チャンク動的配信・アクセス公平性は未検証。
- MIT OR Apache-2.0ライセンスのfastnbt依存を使用したgzip NBTプレイヤー保存は追加済み。ただしAnvilのチャンク読書・既存Minecraftワールドとの互換・ワールドの動的拡張は未実装。
- 公開用のオンライン認証/セキュリティ/権限管理。実機Minecraft GUI接続は別途確認が必要。

現段階の完成判定はRust単体テストと独立したProtocol 5ソケットテストが通ること。Playパケットを送れる状態と「完全にMinecraftを遊べる」は別。

## ホワイトリスト例（whitelist.json）

```json
[
  {"name":"RustTester"},
  {"name":"AnotherPlayer","uuid":"00000000-0000-0000-0000-000000000000"}
]
```

- 参加許可は `name` の大文字小文字を区別しない名前照合で行う。3〜16文字の英数字とアンダースコアのみ許可。重複・JSON破損・ファイル紛失では fail-closed とする。
- `uuid` は公式形式との互換のため入力できるが、**本実装では本人確認に使わない**。offline-modeのUUIDとオンラインアカウントのUUIDを混同してはならない。
- 新しいログインではファイルを再読み込み。接続中の許可取消も周期的にチェックしてキック。書き換え時の部分ファイルは拒否しうるので、一時ファイルから同一ファイルシステムで安全に置き換える。
- WAN公開は禁止。ホワイトリストのみではなりすましを防げない。公開が必要ならオンライン認証/セッション検証または信頼できるVPN境界が別途必要。

## 普通に遊べるバニラ1.7.10への残作業

| 段階 | 主な不足 | 受け入れ条件 |
|---|---|---|
| 1 | 20TPSゲームTick（ブロック更新）、ワールド管理 | 20TPSのtickと状態再現 |
| 2 | チャンク生成・NBT/Anvil・ロード/保存 | 再起動・破損耐性を実機確認 |
| 3 | マルチユーザ/Player List/位置同期 | 2人以上で相互表示 |
| 4 | Survival/Inventory/Crafting | 採掘→アイテム取得→クラフトと保存 |
| 5 | Mob/AI/当たり判定/落下/ダメージ | 代表的なバニラ動作一致 |
| 6 | レッドストーン/液体/ライティング/各種ブロック | 回帰テストで基本的な装置が動作 |
| 7 | Vanilla実機・耐久/セキュリティ試験 | 1.7.10でプレイ可、切断再接続/バックアップ検証 |

現在の成功はあくまで**ネットワークと基礎状態のスモークテスト**。普通に遊べる完成判定ではない。

## マルチプレイヤーの限界

プレイヤー一覧・生成・移動・退出、チャット、ブロックの同期をProtocol 5で行います。同一ユーザー名の2重ログインは拒否。初期設定はlocalhostで、LAN接続には明示的な不安全フラグが必要です。**ホワイトリストの名前照合は本人確認ではないため、名前を偽装できる環境で公開しないでください。** ネットワーク送信用に最大512イベントの有界キューを使用し、低速クライアントではイベントを捨てる可能性があります。インベントリ・サバイバル・アンチチート・動的チャンクは未実装です。
