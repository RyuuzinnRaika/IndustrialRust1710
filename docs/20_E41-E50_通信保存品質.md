# グループE：通信・保存・最適化・品質（41–50）

この文書は実装状態と検証方法を記録する。CI の成功を実機 Java クライアント互換性や長時間 20TPS 達成の証明として扱わない。

## 変更の要点

- 41：`crates/legacy-protocol/tests/protocol5_goldens.rs` に 1.7.10 / Protocol 5 のハンドシェイクと Player List の固定バイト列、TCP フレームの不正長・分割・タイムアウトの回帰テストを追加。既存 `apps/vanilla-server/tests/protocol5_e2e.rs` は Chunk、Inventory、Window、採掘・クラフト等をテストする。
- 42：新規テストで Rust 製の Protocol 5 クライアント4台の同時接続・再接続を検査。**Java 1.7.10 実クライアント GUI を操作する検証は未実施**。
- 43：Hub のチャンク距離でのプレイヤー entity 表示、出力キュー過負荷時の切断検知が既存。Mob / item / projectile の受信者絞り込みは未完。
- 44：既存 `chunk_pipeline.rs` は bounded channel（32件）と2つの zlib worker を持つ。生成・ディスクI/O・送信を完全非同期化したわけではない。ワールドミューテックス中の圧縮処理は避けている。
- 45：通常サバイバルでのブロック配置（ドアを含む）・ベッド配置・耕地化の world+inventory を同じ redo ジャーナルで更新。既存の拾得/DeathDrop/コンテナ移動のジャーナルも継続。起動時に復元を先行実行し、ログ破損時は起動を停止する。symlink とディレクトリ同期処理を改善。採掘ドロップやその他の全保存経路については個別監査が残る。
- 46：既存の `.mca` 形式は **export/import の限定スナップショット**。Anvil を本番・主保存形式として使用する機能は未実装。現行 `.irw` を安全な形式のまま維持する。
- 47：TileEntity NBT の完全な保存・復元は未実装。既存 importer が tile entity を拒否する仕様に注意。
- 48：10秒ごとの実測 JSONL (`world/*.metrics.jsonl`) を新しい `metrics-summary` で集約。processed TPS、ticks missed、tick delivery ratio、worst-window P95/P99 MSPT、ピーク RSS、最大同時接続数を算出し、性能しきい値を指定できる。
- 49：`/list`、`/save` は既存。権限つき `/tp`、`/gamemode`、`/time`、`/weather`、`/difficulty` と whitelist の管理コマンドは未実装。**オフライン名前認証を OP 権限として扱うことは危険**。
- 50：プロトコルの不正入力、4人接続、再接続、ジャーナルの二相リプレイ、破損・symlink のテストを追加。24時間などの長期 soak test と実メモリプロファイルは未実施。

## 実行コマンド

```sh
cargo fmt --all -- --check
cargo test --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release -p vanilla-server
```

実負荷サーバのメトリクスを生成したあと：

```sh
cargo run --release -p vanilla-server --bin metrics-summary -- \
  world/flat.metrics.jsonl \
  --min-tps 19.0 \
  --min-tick-ratio 0.95 \
  --max-p99-mspt 50 \
  --max-rss-mib 512
```

この値は**サンプルしきい値**であり、達成を確認した値ではない。CI でしきい値を判定するときは、同一ハードウェア上で同一ワールド・プレイヤー数・操作パターンを固定して測定する。異なるマシンの記録同士を生の TPS だけで回帰と判定しない。

## 実機検証（手動）

Java Edition 1.7.10 の**無改造**クライアントを複数起動し、ホワイトリストにテストユーザー名を追加してサーバへ接続する。ワールド入場・チャンク描画・採掘・ブロック設置・インベントリ移動・作業台・チェスト・かまど・死亡/復活・再接続を実施する。各操作についてクライアントA/Bの状態が一致するか、再起動後のインベントリ・地形・チェストが一致するかを確認する。保存中の `kill -9`（Linux）等は **必ずコピーしたテストワールドでのみ**実行し、ログの redo 復旧を確認する。Windows のディレクトリ fsync 保証は Linux と異なるため、クラッシュテストも OS 別に行う。

## 安全上の制約

サーバは引き続きオフラインモードであり、ユーザー名の所有者確認がない。信頼できないネットワークへ公開しない。保存先の複数ボリューム跨ぎ、共有ファイルシステム、同じワールドを複数サーバプロセスが同時に書く運用は未対応。テストで確認するまで main への自動統合は行わない。
