# 要件定義書 v0.2 — IndustrialRust1710

- 作成：2026-10-19
- 状態：要件定義（未検証項目を明示）
- 対応対象：Minecraft Java Edition **1.7.10**、Forge **10.13.4.1614**基準、Minecraftプロトコル **5**
- 目的：既存の1.7.10工業化Modを活用し、Rustネイティブ計算／段階的なJavaバイトコード変換／互換ランタイムの研究によって、実測に基づく高速化を達成する。

## 0. 想定利用者と用語

サーバー管理者は、既存の1.7.10 Modpackのクライアントを維持して大規模工業化ワールドを運用したい。対象Modpack・Mod名はまだ選択されていない。まず汎用のForge 1.7.10基準環境を整え、テスト用Modから段階的に検証する。

- 「JARをロード」：実行環境にMod JARを認識させること。処理の正しさまでは含まない。
- 「互換実行」：実際の機械機能、通信、アイテム保存、ブロック配置が元環境と一致すること。
- 「Rustへコンパイル」：Javaクラス／バイトコード中の**サポート済み部分**をネイティブ処理へ変換し、互換ランタイム／アダプターを通して実行すること。
- 「無変更Mod対応」：配布されたJARにパッチや変換前処理を要求せず、Forgeベースラインと同等に実行すること。初期はLegacy-JVMモードのみで成立を検証する。

## 1. 対象と非対象

### 対象
- Minecraft Java 1.7.10のサーバー側機能、ForgeのロードおよびFML互換経路。
- 既存Java製工業化Modの読み取り・分類・依存解決・互換動作の検証。
- 工業ネットワーク／機械演算のRust高速化、負荷計測、データ保護。
- サーバーを中心としたLinux/Windows上の起動・診断・デプロイ。

### 初期対象外
- Javaクライアント側ModのRust化、Minecraft 1.8以降、NeoForge/Fabric互換、Bedrock互換。
- 既存のすべてのForge 1.7.10 Mod JARを無改変でRustネイティブ実行できるという保証。
- 未許諾のMod、Minecraft資産、改変された配布物の再配布。

## 4. 非機能要件

| ID | 要件 | 測定 / 合格基準 |

| PERF-002 | Java同条件との比較 | 同じModpack、同じワールド、同じCPU/RAM/SSD、同じプレイヤー/機械負荷で3回以上比較 |
| PERF-003 | ネイティブ化の有効性 | 限定処理は処理時間の改善を確認し、JNI/IPC込みの端から端までの効果で判定 |
| PERF-004 | 再現性 | OS、CPU、Java/JVM、rustc、ビルドフラグ、Mod/JAR hashes、warm-up手順を保存 |
| CORR-001 | 資源の保存則 | アイテム・液体・エネルギーに消失/重複がない（ルールに定義された生成・損失を除く） |

## 5. 実行モード / 成果の扱い

| モード | JAR | 世界状態の所有者 | 想定用途 | 現在 |
|---|---|---|---|---|
| A: Legacy-JVM | Forgeがそのまま実行 | Forge/JVM | ベースラインと互換維持 | 未統合 |
| B: Hybrid-Offload | Forge実行＋選択した関数をRustへ移管 | Forge/JVM | 性能改善の本命 | 未実装 |
| C: Rust-Native | 対応Mod機能のみRust実行 | Rustサーバー | 長期的な1.7.10互換 | 未実装 |

JARを読めることは互換実行でも、Rustへの変換成功でもない。モードAはRust製ゲームサーバーではなく、目標へ至る検証・移行手段である。

## 6. 完了判定

- **MVP（Stage A）**：Forge 1.7.10の既存Modでの実行ベースライン、Mod/JAR解析レポート、Rust工業計算テスト、同条件の性能データが揃う。
- **実用版（Stage B）**：少なくとも選定した工業化Modの1機能でRust offloadの結果一致、速度改善、セーブ安全性を証明。
- **長期成果（Stage C）**：対応範囲を明示したRustネイティブの1.7.10ゲームサーバーにModdedクライアントが接続・操作できる。全Mod互換は独立した追加目標。

## 7. 未確定の判断（開発を止めない）

- 対象Mod／Modpack：「その他」で個別名称未指定。まず再配布可能なテストModで着手。
- Java実行環境：通常Forge 1.7.10はJava 8ベース。GTNH等の独自更新系は専用サーバーパッケージ／Java 17–21が必要な場合があるため別マトリクス管理。
- Rustサーバーの下地：Pumpkinは現行版対応中心であり、1.7.10対応済みではない。移植コストと独立実装を先に比較する。
- 目標性能：工場規模・CPUを定義した測定シナリオで確定し、数字だけを先に保証しない。

## v0.3 変更管理（2026-10-19）— 実装順序の再決定

上のv0.2「実行モードA→B→C」は実装順序ではなく比較用モードの説明に変更する。**Rust-Nativeをメインライン**、Forge Legacy-JVMは差分検証のためにのみ使用する。根拠と新優先順位は [`10_Rustネイティブ優先方針.md`](10_Rustネイティブ優先方針.md) を優先する。

| ID | 優先 | 追加・変更要件 | 受け入れ条件 |
|---|---|---|---|
| NAT-001 | P0 | RustネイティブでMinecraft 1.7.10 protocol 5の接続段階を実装 | Status/Ping → Login → Playを別々に実機検証 |
| NAT-002 | P0 | Vanilla 1.7.10の最低限のゲームループ実装 | クライアントログイン、チャンク表示、設置、保存、再起動が成功 |
| NAT-003 | P0 | Forge/FML互換を実装する | 対象Mod構成とModIdDataなどの整合性が確認された場合にのみ認証成功 |
| NAT-004 | P1 | Rustだけで工業機械の動作と保存を実現 | 機械・配管の操作/保存とアイテム・エネルギー保存則を検証 |
| NAT-005 | P1 | Java Mod→Rust変換を独立処理系として提供 | 対応部分の変換結果をJava参照値と差分比較。非対応部分はレポート出力 |
| NAT-006 | P0 | 不完全な互換実装を偽って公開しない | ステータス、ログ、互換表、APIごとの対応状況を区別 |
