## 起動・診断

- `cargo run -p vanilla-server -- --check-config` は `server.properties` を検査し、ネットワークを開かない。オフラインモードはループバックのみを許容。
- `cargo run -p vanilla-server -- --verify-world ./world` は `level.dat` か `flat.irw` を判定し読み取りのみ行う。作業中のトランザクションがあれば失敗し、勝手に復旧しない。
- `server.properties` の `level-type=DEFAULT` と `level-seed=文字列またはlong` を組み合わせると、新規IRW3バイオームワールドのシードに適用。既存ワールドと一致しない場合は起動拒否。`FLAT` と非空シードの組合せも意図しない非フラット生成を防ぐため拒否。
- `/stop` はOSコンソールのみ。接続中のプレイヤーを切断して保存した後、tick処理を止める。オンライン接続・資格認証は未対応。
- `cargo run -p vanilla-server -- --world ./world/flat.irw --backup-rotate ./backups 5` は**オフライン専用**。稼働中は`session.lock`が取得できず失敗する。管理者は停止後の定期メンテナンスとしてcron/タスクスケジューラから呼び出す。公開運用の定期ホットバックアップを保証しない。

## J96 データ移行の境界

本家形式の移行前に `cargo run -p vanilla-server -- --prepare-anvil-copy ./original-world ./migration-working-copy` を実行できる。既存の `level_dat.rs` / `legacy_world_inspect.rs` で元ワールドを検証した後、別名の新規ディレクトリに再帰コピーし、バイト一致とAnvil構造の再検査を行う。変換先が既存の場合は拒否する。元ワールドへの `session.lock` 作成も行わない。これは**元データを壊さない移行作業コピーの準備**であり、IRWへの互換変換を完了させるものではない。既存の `anvil_import.rs` / `anvil_export.rs` も従来どおり限定変換専用とする。未知のTileEntityやMod NBTの無損失移行を宣言しない。実運用ワールドはまず管理者が手動で複製し、複製先で読み取り専用検査→限定的変換→再検査、という手順を踏む。変換できない要素が1件でもあれば本番への置換は禁止。

## J97 クライアント実機試験

`docs/group-e/2026-10-21-E42-vanilla-client-e2e.md` の42-01〜42-09を統合受入基準とする。公式クライアントや資格情報はGitへ保存しない。人間によるGUI受入証跡が得られるまではBLOCKED/NOT_RUNとする。

## J99/J100

`workflow_dispatch` または `v*` タグで `.github/workflows/release.yml` がWindows/Linux用にビルドし、`BUILD-MANIFEST.txt`、`Cargo.lock`、`SHA256SUMS` を同梱する。SHA256は同じジョブ内で照合する。これは出自検査であり、完全なbit-reproducibleビルドの証明ではない。CIの品質ゲートは別途 `ci.yml` による。
