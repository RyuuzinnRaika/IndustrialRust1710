# F51–F60 follow-up: operations hardening (2026-10-25)

This follow-up uses the **2026-10-25 F51–F60 audit numbering**, which differs
from the older security feature numbering in `docs/26_F51-F60_管理認証セキュリティ_段階実装.md`.

## Implemented in this PR

- **F51 (unit-level only):** The existing Mojang session profile parser is
  extracted into a network-free function, with tests for canonical UUID
  formatting, mismatched usernames, malformed or missing IDs and invalid JSON.
  This is not the real session-server or unmodified-client acceptance test.
- **F55 (partial):** The opt-in maintenance supervisor now requires a *new*
  rotating backup and invokes the isolated `verify_backup_restore.py` restore
  drill before restarting the server. A failed /stop, backup, or restore drill
  prevents the managed server from restarting. No online hot copy is attempted.
  Regression tests cover missing backups and restore-drill failures.
- **F56 (partial):** `--verify-world` traverses offline and Mojang-verified
  UUID player namespaces, loads inventory / survival inventory / XP /
  achievements / gamemode sidecars, rejects malformed UUID file names,
  non-regular entries and unsupported player artifacts. Device, decoration,
  hanging, minecart, scoreboard, gamerule and map saves are inspected too.
  This remains a **read-only format validation**, not proof of all semantic
  cross-file invariants.
- **F57 (partial):** The non-destructive `--prepare-anvil-copy` path now
  rechecks complete source and stage tree bytes and names immediately before
  publication. It **does not** convert arbitrary Minecraft/Forge worlds to
  the live IRW format. Source worlds must be stopped, as lock-free snapshot
  inspection cannot exclude concurrent writers.
- **F58 (partial):** Linux/Windows binary workflows now launch the resulting
  native server with `--help` as a packaging smoke check. This is not an
  end-to-end unmodified Java client validation.
- **F59 (partial):** `rust-toolchain.toml` pins Rust 1.90.0, rustfmt and
  clippy. **`Cargo.lock` is still absent**; builds do not yet qualify as
  cross-run dependency-reproducible. Generate and review a lockfile with
  `cargo generate-lockfile`, commit it, then use `--locked` consistently.
- **F60 (instrumentation):** The synthetic Protocol 5 load driver computes
  RSS change and first/second half TPS over >=6 stable same-player windows;
  optional `--max-rss-growth-mib` and `--min-tps` gates fail closed.
  Long-running soak tests have **not** been executed in this change.

## How to exercise the operational paths

```sh
python3 -m unittest discover -s tools -p 'test_*.py' -v
cargo fmt --all -- --check
cargo test --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings

# A real server binary and a STOPPED test world are required:
python3 tools/maintenance_supervisor.py \
  --server ./target/release/vanilla-server \
  --world ./test-world/flat.irw --backups ./test-backups \
  --keep 7 --every-hours 24 -- --bind 127.0.0.1:25565

# Synthetic load, not a Java GUI or Mojang authentication acceptance:
python3 tools/e48_load_benchmark.py \
  --server ./target/release/vanilla-server \
  --output ./soak-results-001 --seconds 7200 \
  --warmup-seconds 30 --min-tps 17 \
  --max-rss-growth-mib 512
```

The E48 tool runs four player-count phases; `--seconds 7200` therefore
requests roughly eight hours of measured load plus warmup and verification.
Use a new output path each time; samples are for one isolated run and the
memory-growth threshold is an example policy, not a leak-proof criterion.

  continuity, and UUID namespace separation.
- **F52/F53:** OP/BAN/Kick/UUID permissions and persistence tests with
  simultaneous real players and restart. Existing source-level tests do
  not replace real multiplayer acceptance.
- **F54:** Prove that /stop joins *all* workers and sessions and durably
  flushes world/player/container state under load and failure injection.
- **F55/F56:** Full snapshot manifest, semantic cross-file referential
  validation, and independent clean-host restore and disaster tests.
- **F57:** Lossless world and player conversion including modded NBT/data,

  Until then, refuse destructive automatic migration.
- **F58/F59:** Installable Windows/Linux artifacts on real target machines,
  committed Cargo.lock, pinned runner images/actions, independent build

- **F60:** Actual multi-hour/day memory, TPS, disk, reconnect, restart and
  failure-injection soak evidence from controlled machines.

Do **not** publish a production service on the strength of these partial
checks alone.

## F55: 復元試験成功まで旧バックアップを保持（2026-10-26）

`tools/maintenance_supervisor.py` を使ったオプトインの自動バックアップでは、以前はRustの`--backup-rotate`が指定された世代数を即時整理し、その後に独立した復元試験を実行していた。新しいバックアップの復元試験が失敗した場合、先に削除した旧世代を取り戻せない危険があった。

変更後の順序:

1. 管理下のサーバーを`/stop`で正常終了させ、ワールドを読み取り専用検証する。
2. 既存の**マーカー付き所有バックアップ**を数える。`--backup-rotate`には既存世代を削除しない一時的な保持数を渡して、新規バックアップを作成・検証する。
3. 新しいバックアップが一意に識別できること、所有マーカーが正しいこと、既存世代が残っていることを確認する。
4. 新規バックアップを隔離された一時ディレクトリへコピーし、復元ドリルを正常完了させる。
5. **この後で初めて**指定された保持数まで古い所有バックアップを削除する。未知のマーカー・通常ディレクトリ以外・`backup-`プレフィックスだけの外部ディレクトリは削除しない。時計が巻き戻って新規バックアップ名が古くソートされても、新規世代を保護する。
6. すべて成功した場合に限り管理サーバーを再起動する。復元・削除が失敗した場合は停止したままにする。

Rustの`--backup-rotate`が最大100世代という制限を持つため、所有バックアップが既に100世代ある場合は古いデータを削除せずに自動処理を拒否し、管理者による手動アーカイブを必要とする。

`python3 -m unittest discover -s tools -p 'test_*.py' -v` で、復元失敗時の既存世代保持、成功後の世代整理、外部ディレクトリ非削除、時計巻き戻り、上限到達の回帰テストを実行できる。ローカルファイルシステム上での運用改善であり、災害復旧や異ホスト移行、長期保存媒体の実証までは完了していない。
