## 検証
```sh
cargo fmt --all -- --check
cargo test --workspace --all-targets --locked
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release --locked -p vanilla-server --bins -p legacy-status-server
cargo run -p vanilla-server --bin vanilla-check-config -- --check-config server.properties
```
上記の CI は push 時に実行される。実際の Windows/Linux 成果物を確認するには GitHub Actions の Release binaries を手動実行する。

## 起動
展開したバイナリとワールド／設定は別に管理する。Linux は `./vanilla-server --help`、Windows は `vanilla-server.exe --help` で起動引数を確認できる。 `--online-mode` を有効にしない状態で公開ネットワークへ出さない。世界データの更新前に停止・バックアップを実施する。

## 2026-10-25 J93 読み取り専用ワールド検査の拡充

- `players/verified/<uuid>.dat` の認証済みプレイヤー用名前空間も走査する。UUIDは小文字正規形のみ受け付け、通常プレイヤーと同様にNBT・Inventory・Survival Inventory・XP・Achievements・Gamemodeを検査する。検査によって新たな保存ファイル、セッションロックや書籍サービスは生成しない。
- 保存形式の単体テスト、正常なUUID別プレイヤーの検出、各追加サイドカーの破損拒否、UUID不正名拒否を追加した。

これは**J93の部分実装**であり、保存ファイル間の論理的相互参照、全テレメトリ、未知のサイドカー/孤立ファイル、電源断の瞬間的整合性を完全に検証するものではない。検査が成功してもバックアップと実クライアントでの復旧試験が必要。

## 2026-10-26 F54: /stopワーカー回収と2接続検証（部分実装）

- 明示的な`/stop`を受け付けると新規TCP接続の受付を終了し、全プレイヤー処理を切断イベントで終わらせてプレイヤーのNBT・インベントリ等を保存し、シミュレーションワーカーの終了を待ってから全ワールド・サイドカーを最終保存する。
- クライアント処理・Tick・Hopper・Brewing・Projectile・Clock・Consoleのいずれかがpanicしても、最初の`join()`失敗で最終保存処理を中止しない。残りのワーカーを回収した後に保存を試み、panicを発見した停止は成功と報告せず異常終了コードで通知する。
- 接続処理スレッドのpanicを再回収時に検出した場合も新規受付を中止し、既存のプレイヤーへ停止を通知する。緊急停止時に入力待ちでブロック中のコンソールスレッドは非移植的なstdin強制終了をしない代わりに、以後の入力を処理しないよう停止フラグを確認し、最終保存後のプロセス終了を妨げない。
- ネイティブRust Protocol 5 TCP統合試験で2人が接続中に`/stop`し、双方の理由付きKick、両プレイヤーのNBT・インベントリ保存、創造モードのアイテム保持、TCP待受終了、`--verify-world`による保存後の確認をテストする。

**未完了:** 無改造Minecraft Java 1.7.10クライアント2人での実機E2E、全保存ファイル横断の意味的整合性、複数データ間の完全原子性、停止時の電源断耐性、Windows/Linuxの実配布物上での受入。非常停止の入力待ちスレッド自体は、プロセス終了までブロックする場合がある。

## 2026-10-26 F56: ワールドブロックとコンテナ保存のクロスチェック（部分実装）

- `--verify-world` で IRW ワールドとチェスト (`flat.chests.json`)、かまど (`flat.furnaces.json`)、ホッパー (`flat.hoppers.json`) の保存エントリを**読み取り専用**で突き合わせる。正しいJSON/アイテム数でも、保存位置に対応するブロックがなければ孤立したコンテナとして検査を失敗させる。
- 許可ブロックID: チェスト 54、かまど 61（消灯）/62（点灯）、ホッパー 154。保存キーの座標正規形・境界も再確認する。まず各モデルの既存ローダーでデータ整合性を検証し、検証済みの保存エントリだけをチェックする。
- 通常のワールド更新・書き戻しは一切行わない。未復旧のトランザクションジャーナルは引き続き拒否する。
- 回帰テスト: JSON形式が正常でも孤立したチェスト・かまど・ホッパーを拒否。実ブロックを保存後は受理し、かまどは点灯/消灯両方を受理。検証による保存ファイル変更や `session.lock` 新規生成がないことを確認する。

**未完了:** 追加の装置/醸造台/装飾/NBTの相互参照、全ワールドの原子的世代一致、プレイヤーと全エンティティ間の参照、多人数実クライアント受入、および電源断シミュレーション。古いワールドに孤立したコンテナが実際にある場合は、診断は安全側で失敗するが、自動修復やアイテム削除は行わない。
