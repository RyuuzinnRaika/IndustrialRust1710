# J91〜J100 保存・運用・品質の統合状況

## この変更で追加
- **J94 一部実装:** 読み取り専用の事前検証コマンド。 `cargo run -p vanilla-server --bin vanilla-check-config -- --check-config server.properties`。既存の安全制約と共通の `server_config.rs` パーサーを使用し、設定エラーと危険な待受方法を通知する。未知のキーは既存パーサーが警告する。実サーバーを起動しない。ファイル名を省略するとカレントディレクトリの `server.properties` を検証する。現行の本体 `vanilla-server --check-config` に統合したわけではない。
- **J99 一部実装:** 手動実行または `v*` タグで Windows/Linux の release バイナリを別々に作成する Actions。成果物にはサーバー2本と設定検証ツールが含まれる。
- **J100 一部実装:** 成果物ごとの SHA256、ソースコミット、Rust/Cargo バージョン、Cargo.lock 自体を添付する。これは記録・改ざん検知であり、第三者による再現ビルドの一致証明ではない。

## 検証
```sh
cargo fmt --all -- --check
cargo test --workspace --all-targets --locked
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release --locked -p vanilla-server --bins -p legacy-status-server
cargo run -p vanilla-server --bin vanilla-check-config -- --check-config server.properties
```
上記の CI は push 時に実行される。実際の Windows/Linux 成果物を確認するには GitHub Actions の Release binaries を手動実行する。

## 起動
展開したバイナリとワールド／設定は別に管理する。Linux は `./vanilla-server --help`、Windows は `vanilla-server.exe --help` で起動引数を確認できる。 `--online-mode` を有効にしない状態で公開ネットワークへ出さない。世界データの更新前に停止・バックアップを実施する。
