# D35 エンチャント台：実装境界 (2026-10-23)

## このブランチで対応すること
- Protocol 5: ブロックID116による GUI 開閉、1入力+36プレイヤースロット、3つのレベル表示プロパティ。
- 周辺本棚の判定（上下2段、間隔1ブロック、上限15）と Java Random の3択コスト計算。
- 持ち物の移動、単品取り出し、Shift移動、GUI終了時の返却。
- Inventory保存ファイルに入力中のアイテムを保持し、満杯時は保存したまま再試行可能。
- C11 の不正または未対応なエンチャント選択でアイテム・XPを変更しない。

## 未完成の内容と安全上の制約
- **実際のエンチャント付与は無効**。サバイバル用 `Stack` が任意NBTを保持しないため、未知NBT・他のエンチャントを消してしまう危険がある。
- `xpSeed` の完全な1.7.10同期、エンチャント種別/レベル/競合判定、エンチャント書への変換は未実装。
- C11 は読み取りのみ。サーバは状態を再送し、課金やアイテム消費を行わない。
- GUIを切り替える前にクライアントは従来どおり Close Window を送る。異常終了時も入力はファイルに残す。

## 次の完了条件
1. NBTを未知タグを含めて無劣化で読み書きできる ItemStack 構造を導入する。
2. Inventory、全Window、地面アイテム、Entity、各保存形式、Protocol 5 の全経路を移行・検証する。
3. エンチャント付与処理に正しいXP要求・消費・候補生成を追加し、サーバが検証してから更新する。
4. 無改造 1.7.10 クライアントでGUI、金床、再接続、失敗時復旧を試験する。
