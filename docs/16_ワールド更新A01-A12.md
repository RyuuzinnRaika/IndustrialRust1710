# ワールド更新 A01〜A12 (2026-10-21 作業ブランチ)

対象: `apps/vanilla-server` / Minecraft Java Edition 1.7.10 (Protocol 5)。
本変更は **Rustのみ** でワールド更新の基本機能を実装するものであり、旧版Minecraftの完全再現ではありません。

## コードと動作

| ID | 変更 | 現段階の制約 |
|---|---|---|
| 01 | 20TPS 水源・減衰・再生成・ソース除去時の逆伝播 | バニラの経路探索・流れの優先順位は簡略 |
| 02 | 溶岩4tick間隔、接触で黒曜石/丸石/石 | ネザーの速度設定なし |

| 06 | 天空光の縦列更新と発光ブロック光の伝播、チャンク光配列の送出 | 横方向の天空光の広がりは未対応、動的光の全クライアント再送は未完成 |

## 保存形式

- IRW1: 旧フラット。読み書き変更なし。
- IRW2: 従来の `--terrain-seed`。従来の `terrain::block` と `terrain::surface` を変更しない。
- IRW3: 新規 `--biome-seed 42 --survival`。新形式のため必ず別の `--world` を指定すること。
- すべての変更ブロックは既存のスパース編集保存に入れ、キューは再起動時に復元する。
- 時間/天候・ランダム更新位相は永続化していないため、休止中の追いつき計算はしない。
- 葉のドロップはワールドブロック保存後にエンティティを保存する。障害時はアイテム損失の可能性があるが重複生成は抑止する。

## ローカル・CI テスト

```sh
cargo fmt --all -- --check
cargo test --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release -p vanilla-server
```

検証すべきシナリオ: 源流を抜いた水の消滅、ピストン拡張/収縮、レバーOFF時の信号消滅、保存再起動後の成長状態、農業/流体の同時Tick、チャンク境界の照明、上限64件での公平性。
