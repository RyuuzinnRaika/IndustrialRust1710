# Group A: A01〜A10 ワールド・地形・ディメンション実装監査（2026-10-23）

対象: `apps/vanilla-server`、Minecraft Java Edition 1.7.10 / Protocol 5。

## この変更で実装すること

- A10（部分実装）: `DimensionWorlds::load_all` で Overworld/Nether/End の独立した `Arc<Mutex<World>>` を同時にロードし、シード・次元ID不一致時に起動を拒否。
- A10（部分実装）: `world(dimension)` / `path(dimension)` で保存対象を次元に紐付ける。地形の編集を他の次元に誤って書き込まない。
- A10（部分実装）: `resolve_arrival(source,target,x,y,z)` で 8:1 換算またはエンドの固定到着基準を設定し、**移動先の** ワールドで安全な立ち位置を検索。見つからなければ移動要求は拒否すべき。
- A10（検証）: 範囲外・非有限座標、ワールドの次元不一致を拒否。3次元の互いに独立したブロック変更の保存・再読込・別シード拒否をテスト。
- IRW4 の生成関数は**変更しない**。既存IRW4は編集されていない領域をシードから再生成するため、同じ保存バージョンの地形アルゴリズムを変えるとワールドが破損したように見えるため。

## A10 本実装のために次に必要な接続

1. サーバー起動時に単独 `World` だけでなく `DimensionWorlds` を保持する。ただし現在の `--world` 単独運用、既存の IRW1〜IRW4 の保存場所を勝手に移さない。3次元の `session.lock` と未確定ジャーナルは起動時に先に検証/復元する。
2. セッション毎に現在の `Dimension` を保持。ワールドごとの Mob、チェスト、かまど、地面アイテム、地図、時間・チャンク、プレイヤー一覧をルーティングし、次元を跨ぐ誤配信を防止する。
3. ネザーポータルのフレーム検出、プレイヤー接触継続時間・再移動クールダウン、出口ポータル探索・生成。ディメンション移動で `0x07 Respawn`、旧チャンク解放、移動先チャンク送信と位置補正を正しい順序で送信する。
4. 遷移直前にプレイヤー・インベントリ・体力を保存し、旅行チェックポイントを同じプレイヤーIDに関連付ける。クラッシュ復旧と二重移動・アイテム複製防止をテストする。
5. エンドの帰還条件・ドラゴン戦・リスポーンを接続する。1.7.10の本家クライアントを使ってE2E検証する。
