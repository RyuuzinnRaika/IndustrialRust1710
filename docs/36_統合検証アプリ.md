# Minecraft 1.7.10 統合検証アプリ（industrial-verify）

Rust製のローカル検証ランナーです。**GitHub Actionsは起動しません。** 本番ワールドに接続したり、保存データを削除・変更したりしません。

## Windows / Linux: 1コマンド

リポジトリのルートでRustツールチェーンとPython 3を用意した後に実行します。

```powershell
cargo run --release -p industrial-verify -- --automated-only
```

このコマンドは自動試験の合否を終了コードで返します。Rustのfmt、全crate単体/統合/Protocol 5 TCP試験、Clippy、Releaseビルド、サーバー `--help`、Python unittestを実行します。**Rust CI用GitHub Actionsは使用しません。**

## 実クライアントE42の証拠も要求する

標準で `--automated-only` を付けずに実行すると、無改造Minecraft Java 1.7.10実機の証拠がない場合、E42は `NOT_RUN` になり、終了コード **2** となります。

既に実機を操作して証拠を記録したE42 JSONがある場合は、これを一括検証に組み込めます。

```powershell
cargo run --release -p industrial-verify -- --client-report .\acceptance\e42.json --evidence-root .\acceptance\evidence
```

証拠ファイルの作成・封印・検証には、既存の `tools/e42_acceptance.py` を使用してください。E42は9個の人手観察シナリオです。証拠の整合検証がPASSになっても、実際にゲームを操作したことをこのアプリだけで保証できるわけではありません。

## 出力

`target/verification/<commit>-<unix-time>-<pid>/` に次を保存します。

- `report.json` — 各検証の `PASS`, `FAIL`, `NOT_RUN`, 終了コード、ログ
- `format.log`, `tests.log`, `clippy.log`, `build.log`, `smoke.log`, `python.log`、必要なら `e42.log`

終了コードは **0=要求した検証に合格**, **1=いずれかがFAIL**, **2=未実施の必須試験・実行不能・設定エラー** です。 `--output-dir <path>` で出力先を指定できます。

## 検証可能範囲と限界

`cargo test --workspace --all-targets` が既存のProtocol 5 E2E、World、保存、Mob、インベントリ等のRustテストをまとめて実行しますが、これは「全380条件・95要件の受入」や「24実機試験の完了」を意味しません。Forge/Mod、現実のMinecraft Java 1.7.10 GUI挙動、長時間負荷、複数プレイヤー、TPS/MSPT計測、既存ワールドの安全な移行などは、別途受入記録が必要です。

- 既存ワールドの原本を負荷試験・復元テストの入力にしないでください。
- 出力は検証用の証拠であり、失敗をPASSへ置き換える機能はありません。
- Python 3が見つからなければPython側は `NOT_RUN` です。
- CLI実装を変更した場合は、この新しいcrate自身のユニットテストもCargoのworkspace試験に含まれます。
