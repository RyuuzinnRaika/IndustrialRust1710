# E48/E50: 安全停止時の最終テレメトリ永続化

## 変更範囲

- `TickTelemetry::finish` は10秒間隔の通常レポートを待たず、停止直前の未報告サンプルを JSONL に書き出す。
- 同じ `finish` が続いても、正常保存後は同じ計測窓を二重出力しない。
- 定期的な `record` 呼び出しでファイル書き込みに失敗した場合、その計測窓を消さず、次の記録・正常停止で再試行する。
- Tickスレッドの `shutdown` ループが終了した直後に `finish` を呼び、書き込みエラーは標準エラーへ出力する。エラーをワールド保存成功と取り違えない。
- 未処理Tickがない場合は空の記録行を生成しない。

## 自動試験

```bash
cargo fmt --all -- --check
cargo test --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release -p vanilla-server -p legacy-status-server
```

追加回帰テストは、短時間の終了、二重呼び出し、ファイルの代わりに同名ディレクトリを置いた書き込み障害、および空計測窓を含む。

## 制約

この変更は E48 の **テレメトリ欠損対策** であり、1/2/4/8人の本家 Java 1.7.10 クライアントを使った実測を行ったものではない。
プロセス強制終了や電源遮断の場合、ユーザー空間バッファの最終計測窓は書き出せない。書き込み可能なファイルシステムでの正常停止が前提。
E42、E46の本保存形式、全操作横断のE45ジャーナル、E50のSoak/障害注入は別途受入が必要。
