## 共通インターフェース契約

### WorldとProtocolの不可変条件

1. ゲーム状態はサーバーが権威を持つ。クライアントPacketを直接Worldの確定値とみなさない。
2. World座標は符号付き整数X/Z、Y範囲0..255。各Chunkは16×16列。負座標のChunk割当は床除算を使い、負の剰余で差分計算を壊さない。
3. ブロック状態は1.7.10数値IDと4bit metadataを基本とし、後年のブロックステート表現へ無断変換しない。TileEntityは別NBTとして扱う。
4. 送信元セッションのDimensionとepochを明示し、旧ワールドの差分Packetを新Dimensionへ混入させない。
5. Worldの改変、隣接通知、アイテム増減、永続化の順序を仕様化する。保存に失敗した場合はInventoryだけ減る/Blockだけ増える状態を許さない。
6. 固定seed同一入力はChunk生成順・実行スレッド数・正負座標走査順に依存しない。既存IRW世界と本家1.7.10の完全同seed一致は**異なる要求**。

### 互換モードの区分

- **IRW4互換モード:** 現行の独自決定的Generator。古い世界を守るため生成結果を無断変更しない。
- **Vanilla 1.7.10互換生成モード（目標）:** Java実装のGenLayer/Chunk生成規則と同seed・同座標でgolden照合する。現行コード`worldgen.rs`に「NOT Mojang's terrain algorithm」と明記されており、現段階で完了とは記載しない。
- Minecraft Wikiの現行項目は後世の追記を含むため、必ず**History → Java Edition → 1.7.10以前**の時点を確認する。

## 通信・プレイヤー・基本接続

### N01（P0・基盤あり・要受入）

**機能要求:** 1.7.10 Protocol 5 Handshake→Status/Ping→Login→Playの状態機械を厳格化し、違うprotocolを明示的に拒否

- [ ] **N01-01 入力・前提:** Handshakeのnext-stateがStatusならPing/Response、Loginなら認証分岐へ遷移。
- [ ] **N01-02 正常処理:** Login完了前のPlay packetと二重Loginを拒否し、状態を巻き戻さない。
- [ ] **N01-03 異常・拒否:** 切断理由とリモート負荷を記録、他セッションの状態は不変。
- [ ] **N01-04 受入試験:** 実クライアント正常ログイン・誤版・不正state順序の3系統。基準台帳の最小試験「Client 1.7.10正常入場、誤版と破損長さフレーム拒否」も満たす。

- [ ] **N02-01 入力・前提:** VarInt境界0/127/128/最大桁、TCPの1byte分割・複数packet結合を試す。
- [ ] **N02-02 正常処理:** 各frameの読込長が宣言値と一致した場合のみデコード。

## 品質・実装着手順

- 実装の前に関連Issue/既存open PRとmainを比較。重複実装や未マージPRの内容を「本体に実装済み」と書かない。
- 各IDのチェックリストは独立して受入可能だが、機能全体の完了には必要な4条件すべてと統合テスト、無改造1.7.10の実機証跡が必要。
